# Analytics Permissions Guide

## Overview

The analytics system now includes role-based permissions to control who can view and manage analytics data.

## Available Permissions

### View Permissions
- `view_page_views` - View page view analytics
- `view_visitor_sessions` - View visitor session data
- `view_analytics_events` - View custom event tracking data
- `view_analytics_dashboard` - View analytics dashboard widgets

### Delete Permissions
- `delete_page_views` - Delete page view records
- `delete_visitor_sessions` - Delete visitor session records
- `delete_analytics_events` - Delete analytics event records

### Note on Create/Edit
Analytics data is automatically generated by the system, so there are no `create` or `edit` permissions. Users cannot manually create or edit analytics records.

## Default Role Permissions

### Admin Role
Admins have full access to all analytics features:
- ✅ View all analytics data
- ✅ View analytics dashboard
- ✅ Delete analytics records
- ✅ Access all analytics resources

**Permissions:**
- `view_page_views`
- `delete_page_views`
- `view_visitor_sessions`
- `delete_visitor_sessions`
- `view_analytics_events`
- `delete_analytics_events`
- `view_analytics_dashboard`

### Editor Role
Editors have read-only access to analytics:
- ✅ View all analytics data
- ✅ View analytics dashboard
- ❌ Cannot delete analytics records

**Permissions:**
- `view_page_views`
- `view_visitor_sessions`
- `view_analytics_events`
- `view_analytics_dashboard`

## What Each Permission Controls

### `view_page_views`
- Access to Page Views resource in admin panel
- View page view table and details
- See page visit statistics

### `view_visitor_sessions`
- Access to visitor session data
- View session duration and metrics
- See unique visitor information

### `view_analytics_events`
- Access to custom event tracking data
- View event logs and details
- See user interaction events

### `view_analytics_dashboard`
- View analytics overview widget
- View analytics chart widget
- See dashboard statistics

### `delete_*` Permissions
- Delete individual records
- Bulk delete records
- Clean up old analytics data

## Managing Permissions

### Via Admin Panel

1. **Go to Admin Panel:** `/admin`
2. **Navigate to:** User Management → Permissions
3. **Find Analytics Permissions:** Search for "analytics", "page_views", etc.
4. **Edit Permission:** Click edit to assign to roles
5. **Assign to Roles:** Check the roles that should have this permission

### Via Code

```php
use Spatie\Permission\Models\Role;
use Spatie\Permission\Models\Permission;

// Give a role analytics permissions
$role = Role::findByName('editor');
$role->givePermissionTo([
    'view_page_views',
    'view_analytics_dashboard'
]);

// Remove permissions
$role->revokePermissionTo('delete_page_views');

// Give a specific user permission
$user->givePermissionTo('view_analytics_dashboard');

// Check if user has permission
if ($user->can('view_page_views')) {
    // User can view page views
}
```

## Creating Custom Roles

You can create custom roles with specific analytics permissions:

```php
use Spatie\Permission\Models\Role;

// Create a "Viewer" role with read-only analytics access
$viewer = Role::create(['name' => 'viewer']);
$viewer->givePermissionTo([
    'view_page_views',
    'view_analytics_dashboard'
]);

// Create an "Analytics Manager" role with full analytics access
$analyticsManager = Role::create(['name' => 'analytics_manager']);
$analyticsManager->givePermissionTo([
    'view_page_views',
    'delete_page_views',
    'view_visitor_sessions',
    'delete_visitor_sessions',
    'view_analytics_events',
    'delete_analytics_events',
    'view_analytics_dashboard'
]);
```

## Permission Checks in Code

### In Controllers

```php
public function index()
{
    // Check permission
    if (!auth()->user()->can('view_page_views')) {
        abort(403, 'Unauthorized');
    }
    
    // Your code here
}
```

### In Blade Templates

```blade
@can('view_analytics_dashboard')
    <a href="/admin/page-views">View Analytics</a>
@endcan
```

### In Filament Resources

```php
public static function canViewAny(): bool
{
    return auth()->user()?->can('view_page_views') ?? false;
}
```

## Troubleshooting

### User Can't See Analytics Menu

**Problem:** User doesn't see Analytics in the admin sidebar

**Solution:**
1. Check if user has `view_page_views` permission
2. Verify user's role has the permission assigned
3. Clear cache: `php artisan cache:clear`
4. Clear permission cache: `php artisan permission:cache-reset`

### Permission Denied Error

**Problem:** User gets "403 Forbidden" when accessing analytics

**Solution:**
1. Verify user has the required permission
2. Check if permission is assigned to user's role
3. Ensure user is logged in
4. Clear permission cache

### Widgets Not Showing

**Problem:** Analytics widgets don't appear on dashboard

**Solution:**
1. Check if user has `view_analytics_dashboard` permission
2. Verify widgets are enabled in Filament config
3. Clear cache and refresh page

## Security Best Practices

1. **Principle of Least Privilege**
   - Only give users the permissions they need
   - Use read-only permissions for most users
   - Reserve delete permissions for admins

2. **Regular Audits**
   - Review who has analytics access
   - Remove permissions from inactive users
   - Monitor permission changes

3. **Sensitive Data**
   - Analytics includes IP addresses and user behavior
   - Limit access to users who need it
   - Consider data retention policies

4. **Role Hierarchy**
   - Admin: Full access
   - Editor: Read-only access
   - Custom roles: Specific needs

## Testing Permissions

### Test as Different Roles

1. **Create test users:**
```php
$admin = User::factory()->create();
$admin->assignRole('admin');

$editor = User::factory()->create();
$editor->assignRole('editor');
```

2. **Test access:**
```php
// Test admin access
$this->actingAs($admin)
    ->get('/admin/page-views')
    ->assertOk();

// Test editor access
$this->actingAs($editor)
    ->get('/admin/page-views')
    ->assertOk();

// Test unauthorized user
$this->actingAs($unauthorizedUser)
    ->get('/admin/page-views')
    ->assertForbidden();
```

## API Endpoints

The analytics API endpoints respect permissions:

```php
// POST /api/analytics/track-event
// Requires: authenticated user (no specific permission)

// POST /api/analytics/update-duration
// Requires: authenticated user (no specific permission)
```

Note: Public analytics tracking doesn't require authentication, but viewing analytics data in the admin panel does.
